# Claude Prompt Path

## What this guide is
A fully self-contained PageKit guide for running the whole process inside Claude.

## Best use of Claude here
Claude is strongest when you want to keep the artifact chain visible in one conversation and iterate carefully from it.

## What to gather before you start
- a plain-language product description
- your first audience hypothesis
- any customer language you already have
- competitors or alternatives if relevant
- the page you want to create first

## The artifact chain
1. signal doc
2. message spine
3. page architecture
4. proof map
5. first page draft

## Rule
Keep the artifacts in the thread and ask Claude to work from the full chain.
That is where this path gets stronger.

## Step 1 — Signal doc
Use the same signal-doc prompt as the ChatGPT path.
Paste the product description and ask Claude to produce the signal doc only.

## Step 2 — Message spine
Ask Claude to reduce the signal doc into a homepage-oriented message spine.
Tell it to preserve uncertainty and avoid homepage copy.

## Step 3 — Page architecture
Ask Claude to define the homepage job, sections, trust question and proof burden before drafting.

## Step 4 — Proof map
Ask Claude to separate what the page can honestly support now from what still lacks proof.

## Step 5 — First page draft
Ask Claude to draft from the full artifact chain while keeping:
- clarity over hype
- no fake proof
- no inflated mechanism language

## If the draft is weak
Before heavy line editing, ask Claude what source artifact is still missing or too weak.
Common fixes:
- wedge definition
- mechanism brief
- proof brief
- comparison brief

## Core differences vs other tools
- best for iterative refinement with the full chain visible
- stronger than the baseline path for multi-step continuity
- less research-native than Perplexity
