# TaskPilot Message Spine — First Pass

## 1. Core truth
TaskPilot is for teams and operators who already have plans and tasks, but still lose momentum on the work that matters most.

## 2. Target audience
Primary audience:
- founders
- operators
- small-team leads

These are people who feel the cost of unclear follow-through and coordination drag directly.

## 3. Sharp pain statement
The problem is not making a plan.
The problem is keeping important work moving once real execution begins.

Priorities drift, handoffs get messy, blockers stay hidden too long and people burn time chasing status instead of moving work forward.

## 4. Desired shift or outcome
TaskPilot should help the user move from:
- scattered follow-through
- reactive status-checking
- hidden slippage

to:
- clearer momentum
- earlier visibility into what is slipping
- more confident execution

## 5. Strongest language to preserve
- keep work moving
- know what matters now
- catch slippage early
- less status-chasing
- clearer follow-through

## 6. Homepage message implications
The homepage should likely:
- speak to momentum loss, not generic productivity
- frame the buyer as someone who already has tools
- show that the problem lives between planning and execution
- promise more clarity around what is moving, stuck or slipping

## 7. Key trust question to answer
Why is this different from a task manager or project tool we already have?

## 8. Weak directions to avoid
- generic productivity improvement language
- broad team-software positioning
- feature-heavy homepage framing
- inflated control or visibility claims

## Short verdict
This is usable.
It gives the homepage a real center of gravity.
But it still wants one more layer of clarity around what TaskPilot actually does so the homepage does not drift into pure concept language.

## What felt strong
- pain is sharper
- audience is focused
- homepage implication is clear
- avoids the worst generic productivity drift

## What still feels weak
- product mechanism is still vague
- no proof layer yet
- could still drift abstract in the actual homepage draft

## Is this strong enough to advance?
Yes, with caution.
Proceed to a homepage-oriented page architecture / homepage brief step next.
