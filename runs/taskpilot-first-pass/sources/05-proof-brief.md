# TaskPilot Proof Brief

## Why this source exists
The proof layer is still thin.
That is fine, but it needs to be made explicit so the homepage earns trust honestly.

## What we can support now
- a real pain pattern around momentum loss
- a focused audience hypothesis
- a strong contrast with generic task-software framing
- a clear articulation of the execution-gap problem

## What we cannot support yet
- customer quotes
- specific usage numbers
- quantified outcomes
- detailed feature validation
- implementation stories

## What kind of credibility we can use
- category truth
- clarity of problem framing
- specificity of audience
- honest explanation of intended product role

## Trust rule
The homepage should earn trust through:
- precision
- honesty
- useful framing

Not through:
- inflated confidence
- fake customer evidence
- vague claims that sound polished
