# TaskPilot Message Spine

## Core truth
TaskPilot is for people who already have places where work lives, but still need a clearer way to see when important work is losing momentum.

## Target audience
Primary audience:
- founders
- operators
- small-team leads

These are people who feel the cost of follow-through gaps and coordination drag directly.

## Sharp pain statement
The problem is not getting work onto a list.
The problem is noticing, early enough, when important work is drifting, slowing down or getting stuck once execution is underway.

## Desired shift or outcome
Move from:
- reactive status-checking
- hidden slippage
- noisy coordination

to:
- earlier visibility
- clearer follow-through
- more confident execution

## Strongest language to preserve
- keep important work moving
- see what needs attention now
- catch slippage early
- less status-chasing
- clearer follow-through
- less coordination drag

## Homepage message implications
The homepage should frame TaskPilot as:
- a way to spot momentum loss earlier
- a tool for execution visibility, not just task capture
- a product for teams and operators who already have tools but still feel work slipping

## Key trust question to answer
Why is this better for this problem than the task and planning tools we already use?

## Weak directions to avoid
- broad productivity positioning
- project-management-suite framing
- vague AI language
- heavy feature claims without proof

## Current judgment
This is stronger than the first message spine.
The comparison and mechanism layers now give the homepage a more concrete center.
