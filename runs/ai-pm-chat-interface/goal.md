# Run Goal

## What this run is for
Produce a first homepage draft for an AI-first project management tool where everything happens in a Slack-like chat interface — using the full PageKit process including the slop-check pass before committing.

## What success looks like
- A homepage that names the split-context problem (work lives in chat; tasks live in a separate PM tool; someone has to keep both in sync) before introducing the product
- Copy that earns the AI claim by showing what the AI specifically does, rather than asserting it is "AI-powered"
- A clear distinction between "AI bolted onto an existing PM tool" and "AI-native PM built around conversation"
- Proof claims that stay within what is supportable
- A draft that passes slop-check before committing

## What this run is not trying to do
- Position against every PM tool in the market
- Write a features page or pricing page
- Serve enterprise procurement audiences — this is aimed at teams, not buyers

## Starting conditions
No primary source materials. Signal draws from developer and product team community discussion about PM tool fatigue, AI tooling debates, and the split between where work happens (chat) and where it is tracked (PM tools). That limitation stays visible and constrains downstream claims.

## The wedge this run is testing
The PM tool market has a persistent gap: teams do their actual work in Slack or similar chat tools, while project management happens in a separate system that someone has to manually keep up to date. AI bolt-ons (Notion AI, Jira's AI features, ClickUp AI) reduce friction at the edges but do not close the gap — the two systems still exist. The hypothesis: an AI-native tool built around conversation from the start, where the AI extracts structure from work that is already happening, can close the gap rather than paper over it.
