# Run Goal

## What this run is for
Produce a first homepage draft for OpenClaw, a web hosting service — using the full PageKit process from signal doc through page draft.

## What success looks like
- A homepage that does not default to the three hosting category clichés: speed, reliability, price
- Copy that earns a position in a saturated market by being specific about who this is for and what gap it fills
- A clear wedge that distinguishes OpenClaw from both shared hosting (too simple, too slow) and raw cloud infrastructure (too complex, too much DevOps overhead)
- Proof claims that stay within what is supportable
- A page that would make the right developer stop and recognize themselves

## What this run is not trying to do
- Serve every type of hosting customer
- Compete on price in the hero
- Write copy for a features page or pricing page — homepage only in this pass

## Starting conditions
No primary source materials. OpenClaw is a new brand — no customer interviews, no reviews, no sales call transcripts. Signal draws from observed developer conversation about hosting frustrations, publicly available community discussion, and the visible gaps in current hosting brand positioning. That limitation stays visible and constrains downstream claims.

## The wedge this run is testing
The web hosting market has a gap between "push-button platforms" (Heroku, Render, Railway) that are simple but expensive at scale and opaque in their infrastructure, and raw cloud providers (AWS, GCP, DigitalOcean) that give full control but require DevOps investment most small teams can't justify. OpenClaw's hypothesis: **developer control without infrastructure complexity** — for developers who've outgrown platform-as-a-service but don't want to become cloud engineers to host their product.
