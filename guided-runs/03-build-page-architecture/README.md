# Guided Run 03: Build Page Architecture

## Goal

Turn the message spine into a page system rather than isolated copy tasks.

## Output

- page architecture doc

## Core questions

- what pages should exist?
- who is each page for?
- what job does each page do?
- how do pages relate to one another?

## Quality checks

A strong page architecture:
- has clear page types
- preserves strategic distinctions
- makes expansion easier
- does not feel invented page by page
