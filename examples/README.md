# Examples

These examples show PageKit working on real logged runs.

## Current examples
- `taskpilot-run-summary.md` — summary of a fully logged software object run (homepage)
- `vegan-dog-food-second-pass-summary.md` — summary of the fully logged second-pass run on a plant-based dog food brand. First non-homepage first page in the repo. First real exercise of the claim-check step.
- `vegan-dog-food-run-summary.md` — summary of the original lighter second-object sanity check. Superseded by the second-pass run; kept for before/after comparison.

## What these prove
- the process is real
- the system catches ambiguity early
- stronger source materials produce better page copy
- the pattern transfers across different object types
- the first-page-decision step can produce a non-homepage first page (see second-pass)
- the claim-check step at hard severity catches real patterns (see second-pass)

## What these do not yet prove
- that the architecture generalizes beyond one non-homepage object. One more real non-homepage run on a different category is the meaningful next test.
- that the claim-check step holds up on a real (non-fictional) brand where proof-map gaps are more common.

## Important note
The summaries are the public-friendly surface.
The full run folders under `runs/` contain the complete trail.
See `frameworks/run-logging.md` for the difference between fully logged and summary-logged runs.
